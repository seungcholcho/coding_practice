# 힌트 번들로 스테이지 클리어 최소 비용 (프로그래머스)

## 문제 요약

n개의 스테이지를 1번부터 순서대로 클리어한다. 각 스테이지의 해결 비용은 그 스테이지에서 쓰는 힌트권 수에 따라 줄어든다. 마지막을 제외한 각 스테이지에서는 이후 스테이지용 힌트권이 들어 있는 번들을 최대 1개 살 수 있다. 모든 스테이지를 클리어하는 최소 비용(해결 비용 + 번들 가격)을 구한다.

- 2 ≤ n ≤ 16
- `cost[i][j]`: i+1번 스테이지에서 힌트권 j장을 썼을 때 비용 (j = 0 ~ n-1)
- `hint[i]`: i+1번 스테이지의 번들. `hint[i][0]`은 가격, 나머지는 힌트권 번호(스테이지 번호, 1부터)
- 한 스테이지에서 쓸 수 있는 힌트권은 **최대 n-1장** (모든 스테이지 공통)

---

## 1차 시도: 그리디 → 830 (오답, 정답은 810)

스테이지마다 "지금 번들을 사면 이득인가?"를 그 시점의 정보로 판단했다.

| 스테이지 | 판단 | 결과 |
|---|---|---|
| #1 | 40원으로 #2에서 20, #3에서 30 절약 → +10 | 구매 |
| #2 | 40원으로 #3에서 10, #5에서 40 절약 → +10 | 구매 |
| #3 | 20원으로 #4에서 40, #5에서 10 절약 → +30 | 구매 |
| #4 | 50원으로 #5에서 40 절약 → −10 | 미구매 |

### 구멍

스테이지 2에서 "스테이지 5에서 40원 절약"은 스테이지 5의 힌트권이 **0장 → 1장**이 된다는 가정이었다. 그런데 이후 스테이지 3 번들도 #5를 주면서 실제로는 **1장 → 2장**이 되었고, 절약액은 10원으로 줄었다.

| 스테이지 | 830원 (번들 1, 2, 3) | 810원 (번들 1, 3) | 차이 |
|---|---|---|---|
| #2 번들 | 40 | – | −40 |
| #3 | 힌트 2장 → 120 | 힌트 1장 → 130 | +10 |
| #5 | 힌트 2장 → 60 | 힌트 1장 → 70 | +10 |
| 합계 | 830 | 810 | −20 |

→ 지금의 판단이 **미래의 선택에 따라** 이득이 되기도, 손해가 되기도 한다. 그리디로는 최적을 보장할 수 없다.

## 2차 시도: 브루트포스 (정답)

### 경우의 수부터 세기

- 번들은 마지막 스테이지를 뺀 **n-1개** (`len(hint) = n-1`)
- 각 번들을 산다/안 산다 → 경우의 수 **2^(n-1)**, 최대 2^15 = 32,768
- 경우 하나마다: 번들 최대 15개 × 힌트권 최대 19장 + 스테이지 16개 ≈ 300번
- 전체 약 1,000만 번 → 시간 안에 가능

### 조합 만들기: 2진법 (비트마스크)

번들이 15개면 "산다/안 산다" 반복문을 15겹 쌓아야 할 것 같지만, 조합을 **정수 하나**로 보면 반복문 한 겹으로 끝난다.

- 번들 3개의 조합 8가지 = 0 ~ 7을 2진법으로 쓴 것 (000 ~ 111)
- 각 자리 = 번들 하나의 구매 여부
- 2진법 자릿값은 오른쪽부터 1, 2, 4, 8, … (예: `101` = 4 + 0 + 1 = 5)

정수에서 각 자리를 꺼내는 법은 **2로 나눈 나머지를 꺼내고, 몫으로 반복**하는 것.

```
6 ÷ 2 → 나머지 0, 몫 3
3 ÷ 2 → 나머지 1, 몫 1
1 ÷ 2 → 나머지 1, 몫 0   → 110
```

주의할 점 두 가지:

- **앞자리 0이 사라진다.** `0001`은 그냥 1이라, 몫이 0이 될 때까지만 반복하면 자리 수가 숫자마다 달라진다. → 자리 수를 **번들 개수로 고정**해서 반복한다.
- **거꾸로 저장하면 편하다.** 나머지가 나오는 순서대로 저장하면 첫 나머지 = 첫 번째 번들. 뒤집을 필요가 없다.

### 힌트권 수 상한

번들을 여러 개 사면 한 스테이지에 힌트권이 n-1장보다 많이 쌓일 수 있다. `cost[s]`에는 0 ~ n-1장의 비용만 있으므로, 넘치면 **n-1장으로 고정**해야 한다. 여기서 n은 스테이지 번호가 아니라 **전체 스테이지 수**라서, 상한은 모든 스테이지에 똑같다.

### 코드

```python
def solution(cost, hint):
    sum_list = []

    n = len(cost)
    bundle_count = n - 1              # 번들 개수 = 자리 수
    cases = []

    # 1. 번들을 구매하는 모든 조합 만들기
    for c in range(2 ** bundle_count):    # 조합 숫자: 0 ~ 2^(n-1) - 1
        binary = []                       # 조합마다 새 리스트
        temp = c
        for j in range(bundle_count):     # 자리 수 고정
            binary.append(temp % 2)       # j번째 번들 구매 여부
            temp = temp // 2
        cases.append(binary)

    for is_hint_bought in cases:
        hint_counter = [0] * n            # hint_counter[s]: 스테이지 s+1의 힌트권 수
        sum_hint_cost = 0                 # 번들 가격 합
        sum_cost = 0                      # 스테이지 해결 비용 합

        # 2. 이 조합에서 산 번들만 반영해 힌트권 세기
        for j in range(len(is_hint_bought)):          # j: 번들 번호 (0부터)
            if is_hint_bought[j] == 1:
                sum_hint_cost += hint[j][0]
                for k in range(len(hint[j]) - 1):     # 가격 칸을 뺀 힌트권 수만큼
                    ticket = hint[j][k + 1]           # 힌트권 번호 (1부터)
                    stage_idx = ticket - 1            # hint_counter 칸 (0부터)
                    hint_counter[stage_idx] += 1
                    if hint_counter[stage_idx] > n - 1:
                        hint_counter[stage_idx] = n - 1

        # 3. 스테이지 해결 비용 + 번들 가격
        for s in range(n):                            # s: 스테이지 번호 (0부터)
            sum_cost += cost[s][hint_counter[s]]

        # 4. 조합별 총비용 저장
        sum_list.append(sum_hint_cost + sum_cost)

    # 5. 최소 비용 반환
    return min(sum_list)
```

## 회고

### 가장 어려웠던 것: 인덱스

한 줄에 번호가 세 종류나 섞여 있었다.

| 하는 일 | 쓰는 번호 | 기준 | 이름 |
|---|---|---|---|
| 번들을 샀는지, 가격 | 번들 번호 | 0부터 | `j` |
| 힌트권이 어느 스테이지에 쌓이나 | 번들 안의 힌트권 번호 | **1부터** → `-1` | `ticket` |
| 스테이지 해결 비용 | 스테이지 번호 | 0부터 | `s` |

처음엔 전부 `i`로 써서 섞였다. 역할마다 이름을 다르게 짓고, 긴 인덱스를 한 줄씩 쪼개니 풀렸다.

```python
ticket = hint[j][k + 1]       # 이게 무슨 값인지
stage_idx = ticket - 1        # 한 줄에 한 가지만
hint_counter[stage_idx] += 1
```

대괄호는 **바로 앞에 있는 것**에서 칸을 꺼낸다. `[hint]`처럼 감싸면 뜻이 완전히 달라진다.

### 배운 것

- 지금 최선인 선택이 미래 선택에 따라 달라지면 그리디는 틀린다. 반례를 표로 그려보면 구멍이 보인다.
- 브루트포스 전에 **경우의 수 × 경우 하나의 비용**을 먼저 계산한다.
- 선택지가 "산다/안 산다"처럼 두 가지씩이면 조합을 **2진법 정수 하나**로 표현할 수 있다. (비트마스크)
- 반복문을 겹치는 대신 **숫자 하나를 세는 반복 한 겹**으로 모든 조합을 만든다.
- 문제의 n은 "전체 개수"인지 "몇 번째"인지 꼭 확인한다.
- `for x in 리스트`의 x는 인덱스가 아니라 원소다. 번호가 필요하면 `range(len(...))`나 `enumerate`.
- 파이썬에 `++`는 없고 `+=`는 있다. 거듭제곱은 `**`, 몫은 `//`, 나머지는 `%`.

### 처음 써본 것

- `2 ** bundle_count` 거듭제곱
- `%`, `//`로 2진법 자리 꺼내기
- 비트마스크로 모든 조합 만들기
