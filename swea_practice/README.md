## 배운 것

### SWEA 입출력

- `T = int(input())`로 시작하는 기본 코드를 믿지 말고 **입력 설명부터** 확인
  - 첫 줄이 T가 아닌 문제도 있음 (View: 테스트 케이스 10개 고정)
  - 케이스 첫 줄이 개수가 아니라 **케이스 번호**인 문제도 있음 (최빈수)
- 한 줄에 숫자 여러 개: `list(map(int, input().split()))`
- 출력: `print(f"#{tc} {answer}")`
- 로컬 테스트: `sys.stdin = open("input.txt")` (제출 전 지우기), 경로는 **실행 위치 기준**

### 에러에서 배운 것

| 에러 | 원인 |
|---|---|
| `TabError` | 탭과 스페이스가 섞임 → VS Code "Convert Indentation to Spaces" |
| SWEA "메모리 에러" | 실제로는 `list`, `len`을 변수 이름으로 써서 내장 함수가 사라짐 |
| `ValueError: invalid literal for int()` | 숫자 여러 개짜리 줄을 `int(input())`으로 읽음 |
| `'list_reverseiterator' object is not subscriptable` | `reversed()` 결과는 인덱스 접근 불가 |

### 시간 판단

- 백만 장자: 최대값 찾고 자르기 반복은 최악 약 5,000억 번 → **뒤에서 한 번 훑기**는 100만 번
- 최대 상금: 교환 경로는 15^10개지만 **배치는 최대 6! = 720개** → 상태를 합치면 약 10만 번 (두 도둑과 같은 아이디어)
- 입력은 어차피 한 번은 다 봐야 한다 → 그 위에 무엇이 더 붙는지로 비교

### 파이썬

- `b = a`는 **복사가 아님**. 복사는 `a[:]`, `a.copy()`. 2차원은 `[row[:] for row in a]`
- `map(함수, 리스트)`: 원소마다 함수 적용
- `a.index(x)`는 **처음** 나오는 위치만
- 동점 처리: `max(d, key=lambda s: (d[s], s))`처럼 기준을 튜플로
- `reversed()`, `map()`의 결과는 리스트가 아님 → 필요하면 `list()`로
