## 문제 요약

루트(자식 1개), 분배 노드(자식 2개 또는 3개), 리프(자식 0개)로 트리를 만든다. 리프를 최대한 많이 만들되,

- 분배 노드는 최대 `dist_limit`개
- 같은 깊이의 분배 노드들은 자식 수가 같아야 함
- 모든 리프의 분배도(부모부터 루트까지 자식 수의 곱) ≤ `split_limit`

- 0 ≤ `dist_limit` ≤ 10^9
- 1 ≤ `split_limit` ≤ 10^9

---

## 문제 분해

### 1. 규칙 이해하기

작은 트리를 직접 그려서 분배 노드 수, 리프 수, 리프마다 분배도를 계산하며 규칙을 확인했다.

- 루트는 **깊이 0**, 자식 1개, 분배 노드로 세지 않는다.
- 규칙 3이 같게 만드는 건 **같은 깊이 분배 노드의 자식 수**뿐이다. 같은 깊이에 리프와 분배 노드가 **섞여 있어도 된다.** (트리가 대칭일 필요는 없다)
- `split_limit`의 n은 스테이지 번호가 아니라 **모든 경로에 똑같이** 적용되는 상한이다.

### 2. 트리를 노드가 아니라 "깊이별 표"로 표현하기

입력이 10억까지라 노드를 하나씩 만들 수 없다. 대신 깊이마다 **(분배 노드 수 D, 리프 수 L, 자식 수 C)**로 표현한다.

- 다음 층 노드 수 = 이 층 D × 이 층 C (깊이는 곱하지 않는다)
- 깊이별 **노드 수만으로는 부족**하다. 노드 수가 같아도 분배/리프 구성이 다르면 리프 수와 분배도가 달라진다.

### 3. 깊이의 상한

경로를 내려갈 때마다 분배도에 2나 3이 곱해진다. 가장 깊이 가려면 2만 곱하는 게 유리하고, 그래도 2^30 > 10억이라 **최대 약 29층**이다. (한 번 나눈 몫이 아니라 **몇 번 나눌 수 있는지** = log₂)

### 4. 2와 3 중 어느 쪽이 유리한가 → 상황마다 다르다

| 상황 | 유리한 쪽 | 이유 |
|---|---|---|
| `dist_limit = 1` | 3 | 분배 노드 하나에서 리프를 최대로 |
| `split_limit = 8`, 분배 노드 넉넉 | 2 | 층을 더 쌓을 수 있음 (2,2,2 → 8 vs 3,2 → 6) |

그래서 고정할 수 없고 **2가 a개, 3이 b개**인 경우를 전부 본다. 2^a × 3^b ≤ split_limit인 (a, b) 쌍은 a ≤ 29, b ≤ 18이라 **약 300개**뿐이다.

### 5. 같은 (a, b)라면 순서는? → 3을 아래에

순서를 바꿔도 분배 노드가 넉넉하면 리프 수는 같지만, **빠듯하면 달라진다.** 위층에서 3으로 나뉘면 아래층 노드가 빨리 불어나 분배 노드를 더 쓴다.

```
[3, 2]: 분배 노드 1 + 3 = 4개
[2, 3]: 분배 노드 1 + 2 = 3개   (리프는 둘 다 6)
```

→ (a, b)마다 **2를 먼저 a번, 3을 나중에 b번** 순서 하나만 보면 된다.

### 6. 층마다 분배 노드를 몇 개 만들까 → 다 쓰는 게 이득

노드 하나를 리프로 두면 리프 1개, 분배 노드로 만들면 2~3개다. 그래서 위층부터,

- 남은 분배 노드가 충분하면 이 층 노드를 **전부** 분배 노드로
- 모자라면 **남은 만큼만** 분배 노드로, 나머지는 **리프**
- 그 아래 층은 전부 리프

`dist_limit = 9`, 순서 `[3, 3, 3]`:

| 깊이 | D | L | C | 남은 | 다음 층 노드 |
|---|---|---|---|---|---|
| 1 | 1 | 0 | 3 | 8 | 3 |
| 2 | 3 | 0 | 3 | 5 | 9 |
| 3 | 5 | 4 | 3 | 0 | 15 |
| 4 | 0 | 15 | | | |

리프 = 4 + 15 = **19**

### 시간

(a, b) 약 300개 × 층 최대 약 30 → 수천 번. 입력이 10억이어도 바로 끝난다.

## 코드

```python
def solution(dist_limit, split_limit):
    if dist_limit == 0:                 # 분배 노드를 못 쓰면 루트 → 리프 하나
        return 1

    # 1. 2^a × 3^b ≤ split_limit인 (a, b) 전부
    combination = []
    a = 0
    while 2 ** a <= split_limit:
        b = 0
        while (2 ** a) * (3 ** b) <= split_limit:
            combination.append([a, b])
            b += 1
        a += 1

    total_leaf = []
    for a, b in combination:
        # 2. 순서: 2를 먼저, 3을 나중에 (분배 노드를 가장 아낌)
        t = [2] * a + [3] * b

        # 3. 위층부터 내려가며 리프 세기
        left = dist_limit               # 남은 분배 노드
        D = 1                           # 이번 층 분배 노드 수 (깊이 1)
        L = 0                           # 지금까지 리프 수
        for C in t:
            left -= D                   # 이번 층 분배 노드 사용
            nxt = D * C                 # 다음 층 노드 수
            if left >= nxt:             # 충분: 다음 층 전부 분배 노드
                D = nxt
            else:                       # 부족: 남은 만큼만, 나머지는 리프
                D = left
                L += nxt - left
        L += D                          # 순서가 끝난 층의 노드는 전부 리프
        total_leaf.append(L)

    # 4. 최댓값
    return max(total_leaf)
```

(제출한 코드에서 `dist_limit == 0`을 반복 전으로 옮기고, 반복 흐름으로 처리되는 `len(t) == 0`, `len(t) == 1` 분기를 지우고, 순서를 `[2] * a + [3] * b`로 줄여 씀. 동작은 같음.)

부족했던 층 다음 바퀴에서는 `left`가 0이 되므로, 그 층 노드가 전부 리프로 세지고 D가 0이 된다. 따로 멈추지 않아도 자연스럽게 끝난다.

## 회고

### 이번 문제의 핵심

- **입력이 크면 "무엇을 세는지"를 바꾼다.** 노드 10억 개 대신, 트리를 결정하는 **선택들**(층마다 자식 수, 분배 노드 수)로 표현하니 경우가 몇백 개로 줄었다.
- **"항상 유리한 선택"이 없으면 전부 시도하고, 있으면 하나만 본다.** 2 vs 3은 상황마다 달라서 (a, b)를 전부 보고, 순서(3을 아래로)와 분배 노드 수(다 쓰기)는 항상 유리한 쪽이 있어서 하나만 봤다.
- 작은 예제를 **손으로 표를 채워서** 규칙을 찾았다. 표의 한 줄이 그대로 반복 한 바퀴가 됐다.

### 막혔던 것

- **깊이는 주어지는 게 아니다.** 입력은 `dist_limit`, `split_limit`뿐이고, 깊이는 내가 정하는 것. 그 상한을 구하는 게 질문이었다.
- **로그.** "한 번 나눈 몫"이 아니라 "몇 번 나눌 수 있는지". 그리고 `log₂(N) = 10억`이 아니라 `log₂(10억)`.
- **표의 칸 의미가 섞임.** D 칸에 분배 노드 **수** 대신 **자식 수**를 적었다.
- **층 처리 로직.** 조건과 분기 내용이 서로 바뀌거나, 두 분기가 같은 일을 하거나, `t[C+1]`로 다음 칸을 보다가 범위 밖 에러. "D = 이번 층 노드 수와 남은 분배 노드 중 **작은 쪽**"으로 표를 먼저 채우고 나서야 풀렸다.
- **경계 상황.** 빈 순서 `[]`(split_limit = 1), `dist_limit = 0`. 처음엔 "고려할 필요 없다"고 생각했지만 제한사항에서 둘 다 가능했다.
- **마지막 층.** 순서가 끝난 층의 노드는 분배 노드처럼 계산돼도 실제로는 자식이 없는 리프다. → 반복 뒤 `L += D`

### 처음 써본 것

- `math.log2`, `math.log(x, 3)`로 상한 확인
- `[2] * a + [3] * b`로 순서 만들기
- 반복문 안에서 다음 칸을 보지 않고 **이번 칸만으로** 결정되게 구조 바꾸기
