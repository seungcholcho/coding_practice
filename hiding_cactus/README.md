# 선인장 숨기기 (프로그래머스)

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/468379

## 문제 요약

m × n 격자 위에 h × w 크기의 선인장 구역을 놓는다. 빗방울이 정해진 순서대로 격자의 칸에 떨어질 때, 선인장 구역이 **가능한 한 늦게** 처음 비를 맞는 위치(구역의 왼쪽 위 좌표)를 구한다. 비를 아예 맞지 않는 위치가 있으면 그곳이 최우선이고, 후보가 여럿이면 가장 위쪽 행, 그다음 가장 왼쪽 열을 고른다.

- 제한: 1 ≤ m × n ≤ 500,000

## 문제 분해

1. m × n 격자에서 h × w 선인장이 놓일 수 있는 위치 중, 비를 가장 늦게 맞는 곳을 찾는다.
2. 선인장의 왼쪽 위 좌표 (i, j)마다, 구역 안 빗방울 순서의 **최소값**을 구한다. 이 값이 그 위치에서 처음 비를 맞는 시간이다.
   - (0, 0)에 놓았을 때 처음 비 맞는 시간 t1
   - (0, 1)에 놓았을 때 처음 비 맞는 시간 t2
   - …
   - (i, j)에 놓았을 때 처음 비 맞는 시간 tn
3. 구역 내 최소값을 구하는 방법
   - 완전 탐색
   - 슬라이딩 윈도우 최솟값 (단조 덱)
4. tn이 **최대**인 곳이 정답이다. → "구역 최소값 중 최대값" 문제

### 핵심 아이디어: 빈칸 처리

비가 오지 않는 칸은 `len(drops) + 1`로 채운다. 어떤 빗방울 번호보다도 큰 값이라서 최소값 계산을 방해하지 않고, 비를 아예 맞지 않는 구역은 최소값이 가장 커져서 "비를 안 맞는 구역 우선" 규칙이 따로 처리하지 않아도 지켜진다.

```python
field = [[len(drops) + 1] * n for _ in range(m)]
for idx, (r, c) in enumerate(drops):
    field[r][c] = idx + 1
```

## solution1: 완전 탐색 (4중 반복문)

필터의 위치(i, j)마다 h × w 칸을 모두 훑어 최소값을 구하고, 최소값이 가장 큰 위치를 고른다.

```python
sets = []
for i in range(m - h + 1):
    for j in range(n - w + 1):
        cur_min = field[i][j]
        for a in range(h):
            for b in range(w):
                temp = field[i + a][j + b]
                if temp < cur_min:
                    cur_min = temp
        sets.append([i, j, cur_min])

results = max(sets, key=lambda x: x[2])
answer = results[0:2]
```

### 처음 써본 것

- 특정 값으로 채워진 m × n 행렬 생성: `[[값] * n for _ in range(m)]`
- `enumerate`로 순서와 원소를 함께 받기, `(r, c)`로 언패킹
- 여러 값을 가진 원소 중 특정 값 기준 최대값: `max(sets, key=lambda x: x[2])`
  - `max`는 동점이면 먼저 나온 원소를 돌려줘서, 위→아래, 왼→오른 순서로 쌓은 `sets`에서 동점 규칙이 자동으로 지켜진다.

### 한계

정답은 맞지만 연산량이 `(m-h+1) × (n-w+1) × h × w`다. m = n = 700, h = w = 350이면 약 150억 번으로 시간 초과.
→ 필터를 옮길 때마다 겹치는 칸을 처음부터 다시 훑는 것이 병목.

## solution2: 2차원을 1차원 두 번으로 쪼개기

최소값은 쪼개서 구해도 같다. 그래서 h × w 구역의 최소값은 "가로 w칸 최소값들의 세로 h칸 최소값"과 같다.

1. `field`의 각 행에 길이 w의 슬라이딩 윈도우 → 구역별 가로 최소값 표 `temp`
2. `temp`의 각 열에 길이 h의 슬라이딩 윈도우 → 구역별 최소값 표
3. 열 단위로 처리해서 표가 뒤집혀 있으므로 한 번 더 전치해 원래 방향으로 (`min_list`)
4. `min_list`에서 최대값을 찾고, 위→아래, 왼→오른 순서로 처음 나온 위치를 반환 (동점이면 좌상단 우선)

결과 표 `min_list[i][j]` = 왼쪽 위가 (i, j)인 선인장 구역의 최소값.

### 한계

`sliding_min` 안의 `min(window)`와 `window.pop(0)`이 구간마다 w칸을 다시 돌아서, 여전히 O(m × n × (w + h)).

## solution3: 단조 덱으로 슬라이딩 윈도우 최솟값 (정답)

`sliding_min`만 덱 버전으로 교체. `solution2`의 나머지 코드는 그대로.

덱에는 **최소값 후보의 인덱스**를 저장하고, 값은 앞에서 뒤로 갈수록 커지는 순서로 유지한다. i번째 값이 들어올 때:

1. 덱이 비어 있지 않고 `arr[dq[-1]] > arr[i]`인 동안 → `dq.pop()`
   (먼저 들어왔는데 더 큰 값은 앞으로 최소값이 될 수 없음)
2. `dq.append(i)` (새 값은 항상 넣음)
3. `i - dq[0] >= w`이면 → `dq.popleft()` (맨 앞 후보가 구간 밖)
4. `i >= w - 1`이면 → `min_list.append(arr[dq[0]])` (맨 앞이 현재 구간의 최소값)

```python
from collections import deque

def sliding_min2(arr, w):
    dq = deque()            # 인덱스 저장 (위치 판단용)
    min_list = []           # 값 저장 (결과)
    for i in range(len(arr)):
        while dq and arr[dq[-1]] > arr[i]:   # 값 비교 → arr[인덱스]
            dq.pop()
        dq.append(i)                          # 인덱스를 넣음
        if i - dq[0] >= w:                    # 위치 판단 → 인덱스 그대로
            dq.popleft()
        if i >= w - 1:                        # 기록 시점 → i 기준
            min_list.append(arr[dq[0]])       # 기록은 값으로
    return min_list
```

각 인덱스는 덱에 한 번 들어가고 최대 한 번 빠지므로 한 줄에 O(N), 전체 **O(m × n)**.

## 회고

**index를 따로 관리하는 예술을 느낌.**

값 자체와 리스트의 인덱스를 분리하는 생각을 하기 너무 어려웠다.

값만 들고 있으면 그 값이 어디서 왔는지(구간 밖인지)를 알 수 없다. 인덱스는 위치를 알려주고, 인덱스를 알면 값도 알 수 있다. 그래서 기본은 인덱스로 관리하고, 값이 필요할 때 리스트에서 불러오면 된다.

- 위치 판단: `dq[0]`
- 값 비교, 기록: `arr[dq[0]]`

명단에는 고유 등록번호를, 내용은 기록부에서.

### 헷갈렸던 것들

- 덱은 윈도우 그 자체가 아니라 **최소값 후보 명단**이다. 덱의 길이는 윈도우 크기와 관계없다.
- 그래서 구간 관련 판단(앞에서 빼기, 기록 시점)은 덱 길이가 아니라 `i`와 인덱스로 한다.
- 최소값 계산은 값이 **들어오는 순간** 조금씩 미리 이뤄진다. 결과가 필요할 때는 맨 앞만 읽는다.
- 순서: 뒤에서 빼기 → 넣기 → 앞에서 빼기 → 기록. 기록 전에 구간 밖 후보를 먼저 빼야 한다.
