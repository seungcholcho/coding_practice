## 문제 요약

n개의 배양체가 n-1개의 파이프로 트리 모양으로 연결되어 있다. 파이프는 A, B, C 세 종류다. 한 번에 한 종류의 파이프를 전부 열었다 닫을 수 있고, 열려 있는 동안 감염된 배양체에서 열린 파이프를 따라 바이러스가 퍼진다. 최대 k번 열고 닫아서 감염시킬 수 있는 배양체 수의 최댓값을 구한다.

- 2 ≤ n ≤ 100
- 1 ≤ k ≤ 10

---

## 문제 분해

### 규칙 확인

- 한 종류를 열면 그 종류의 파이프가 **전부 동시에** 열린다. 감염된 노드에서 열린 파이프를 따라 **여러 칸 연쇄로** 퍼진다. (입출력 예 #2: A를 열면 6 → 5 → 4)
- 같은 종류의 파이프로 연결되어 있어도, 감염된 노드에서 **실제로 이어져 있지 않으면** 퍼지지 않는다. (입출력 예 #1: A를 열어도 9가 감염되지 않았으니 10은 감염되지 않음)

### 경우의 수 줄이기

- **같은 종류를 연속으로 여는 건 의미가 없다.** 열려 있는 동안 이어진 곳은 이미 전부 감염되므로, 바로 또 열어도 새로 감염될 곳이 없다.
- **"최대 k번"이어도 정확히 k번만 보면 된다.** 문을 더 연다고 감염 수가 줄지는 않고, 짧은 순서는 연속 없이 항상 k번까지 늘릴 수 있다.
- 첫 번째는 3가지, 그다음부터는 바로 앞과 다른 2가지 → **3 × 2^(k-1)**, k = 10이면 1,536가지

### 시간 계산

| 단계 | 크기 |
|---|---|
| 문 여는 순서 | 최대 1,536가지 |
| 순서 하나에서 문 여는 횟수 | 최대 10번 |
| 문 한 번 열 때 BFS | 노드 100 + 연결 약 200 |
| 합계 | 약 450만 번 → 충분 |

처음 생각한 "모든 노드 쌍 2중 반복문"은 문 한 번에 100 × 100이고, 한 바퀴로 연쇄가 끝나지 않으면 여러 바퀴가 필요해서 최악 150억 번까지 갈 수 있었다. 실제 연결만 따라가는 **인접 리스트 + BFS**로 바꿔서 해결.

## 풀이

### 1. 문 여는 순서 만들기 (3진법 + 거르기)

지난번 2진법 조합 만들기를 3진법으로 응용했다. 0 ~ 3^k - 1을 3진법으로 바꾸고 `+1`로 타입 번호(1~3)에 맞춘 뒤, 이웃한 두 칸이 같은 순서는 걸러낸다.

- 거를 때는 리스트를 돌면서 **빼지 않고**, 통과한 것만 **새 리스트에 담는다.** (반복 중에 같은 리스트에서 빼면 원소를 건너뛰거나 범위 밖 에러)
- `set`은 떨어진 중복(`A, B, A`)까지 잡아서 이 문제에는 맞지 않는다. 이웃한 값만 직접 비교.
- 3^10 = 59,049개를 다 만들고 걸러도 약 60만 번이라 충분했다.

### 2. 트리는 한 번만 그리기

문을 열고 닫아도 **트리 모양은 그대로**고, 바뀌는 건 **지금 지나갈 수 있는 연결**뿐이다. 그래서 인접 리스트에 `(이웃, 파이프 종류)`를 같이 담아 한 번만 만들고, 탐색할 때 종류만 확인한다.

### 3. 반복 세 겹: 어느 겹에서 무엇을 새로 시작하나

| 반복 | 한 바퀴의 의미 | 시작할 때 할 일 |
|---|---|---|
| 바깥: 순서 | 문 여는 순서 하나를 처음부터 시험 | 감염 상태를 처음 상태(`infection`만)로 되돌리기 |
| 중간: 문 하나 | 그 순서 안에서 문 하나 열고 닫기 | **지금까지 감염된 노드 전부**를 방문 표시 + 대기열에 넣기 |
| 안쪽: BFS | 대기열에서 하나씩 꺼내 퍼뜨리기 | 대기열이 빌 때까지 반복 |

### 코드

```python
from collections import deque

def solution(n, infection, edges, k):
    # 1. 문 여는 순서 만들기
    gate_combination_with_repeat = []
    for c in range(3 ** k):
        combination = []
        temp = c
        for i in range(k):
            combination.append(temp % 3 + 1)   # 타입 1~3
            temp = temp // 3
        gate_combination_with_repeat.append(combination)

    gate_combination = []
    for temp in gate_combination_with_repeat:
        is_repeating = False
        for i in range(len(temp) - 1):
            if temp[i] == temp[i + 1]:          # 같은 종류 연속
                is_repeating = True
        if not is_repeating:
            gate_combination.append(temp)

    # 2. 트리는 한 번만: (이웃, 파이프 종류)
    graph = [[] for _ in range(n + 1)]          # 노드 번호 1~n을 그대로 인덱스로
    for x, y, t in edges:
        graph[x].append((y, t))
        graph[y].append((x, t))

    # 3. 순서마다 시뮬레이션
    total_list = []
    for combination in gate_combination:
        is_infected = [0] * (n + 1)             # 순서마다 처음 상태로
        is_infected[infection] = 1
        visited = [False] * (n + 1)
        q = deque()

        for opened_gate in combination:
            # 문을 열 때마다: 감염된 노드 전부에서 다시 퍼지기 시작
            for i in range(len(is_infected)):
                if is_infected[i] == 1:
                    visited[i] = True
                    q.append(i)

            # BFS: 열린 종류의 파이프만 따라감
            while q:
                node = q.popleft()
                is_infected[node] = 1
                for nxt, gate_type in graph[node]:
                    if not visited[nxt] and gate_type == opened_gate:
                        visited[nxt] = True
                        q.append(nxt)

        total_list.append(sum(is_infected))

    return max(total_list)
```

(제출한 코드에서 `print` 제거, 감염 수 저장과 `max`를 반복 바깥으로, 대기열을 빈 상태로 시작하도록 정리. 동작은 같음.)

## 회고

### 처음 배운 것: 트리 탐색 (BFS)

- 트리는 탐색 전에 **인접 리스트**로 바꿔둔다. "이 노드에서 다음에 갈 곳은?"을 바로 답할 수 있게.
- BFS 규칙은 세 줄: **맨 앞 꺼내기 → 아직 안 간 이웃을 방문 표시하고 대기열에 넣기 → 빌 때까지 반복.**
- **방문 표시와 대기열에 넣기는 항상 한 쌍.** 넣기만 `if` 밖으로 나가면 대기열이 끝없이 차서 끝나지 않는다.
- 연결 방향이 없으니 `visited`가 없으면 두 노드 사이를 계속 오간다.
- 확장: **출발점 여러 개**는 처음에 대기열에 전부 넣기, **특정 연결만 통과**는 이웃으로 넘어갈 때 조건 하나 추가.
- `visited`를 n+1칸으로 만들면 노드 번호를 그대로 인덱스로 쓸 수 있다. (0번 칸은 안 씀)

### 막혔던 것

- **이웃의 이웃을 감염시키는 실수.** 처음 2중 반복문 버전은 "주변에 감염이 있으면 내 이웃들을 감염"시켜서, 감염되지 않은 노드를 건너뛰고 퍼졌다. 감염은 **연결을 한 칸씩 실제로 따라가서만** 퍼져야 한다. → BFS가 이걸 구조적으로 보장한다.
- **값과 인덱스를 또 섞음.** `for i in is_infected`에서 `i`는 0/1 값인데 `visited[i]`로 노드처럼 썼다. 선인장 문제에서 정리한 "인덱스와 값 분리"가 다시 나왔다.
- **기록과 반영은 다르다.** `is_infected`에 감염을 기록해도, 다음 문을 열 때 **대기열로 옮기지 않으면** BFS는 시작하지 못한다.
- **초기화 위치.** 감염 상태를 순서 반복 밖에 두거나 조건부로 초기화하면 순서끼리 결과가 섞였다. 반복이 여러 겹일 때는 값마다 **어느 겹에서 새로 시작하는지** 표로 정리하니 풀렸다.

### 처음 써본 것

- `3 ** k`, `% 3`, `// 3`으로 3진법 조합 만들기
- `collections.deque`로 BFS 대기열
- 인접 리스트에 튜플 `(이웃, 종류)` 담기, `for nxt, gate_type in graph[node]`로 풀어 받기
- 파이썬의 `^`는 거듭제곱이 아니라 XOR. 거듭제곱은 `**`
